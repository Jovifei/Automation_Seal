# 系统架构与安全基线

## 1. 信任边界

系统分为五个信任区：

1. 用户控制区：Codex界面、审批文件和密钥输入。
2. 主机Agent区：OpenClaw主会话，仅用户本人可触发。
3. 沙箱执行区：非主Agent和客户任务，只挂载指定目录。
4. 容器服务区：n8n、PostgreSQL、changedetection.io。
5. 外部互联网区：公开网页、GitHub、模型API和通知渠道。

任何从外部进入的文字、网页、消息和Skill都视为不可信输入。

## 2. 数据流

公开来源先进入研究区，经过清洗、去重和来源检查后进入候选主题。用户批准后才生成产品任务。Codex在隔离工作区实现并测试，产物进入review-queue。人工审批文件校验哈希后，产物才能进入approved。

## 3. 目录隔离

| 目录 | 权限 | 用途 |
|---|---|---|
| `workspace/research` | 研究Agent可写 | 带来源的调研结果 |
| `workspace/products` | 产品Agent按项目读写 | 产品源码和文档 |
| `workspace/review-queue` | Agent只写，用户审核 | 候选交付物 |
| `workspace/approved` | 工作流按审批复制 | 已批准产物 |
| `workspace/quarantine` | 只用于拒绝和可疑文件 | 隔离 |
| `vendor` | 默认只读 | 锁定第三方源代码 |
| `backups` | 备份脚本写 | 数据恢复 |

客户任务必须使用独立目录和Git仓库。不同客户之间不能共享工作树、缓存、提示上下文或输出目录。

## 4. 网络基线

- 所有Web UI只绑定127.0.0.1。
- 数据库不暴露宿主机端口。
- 禁止路由器端口转发。
- 禁止默认启用局域网访问。
- 外部Webhook必须经过用户批准，并优先使用出站通知而非入站公网服务。
- 如未来需要远程访问，另行完成Tailscale/反向代理威胁模型，不直接修改本配置。

## 5. 凭证基线

- `.env`、`config.toml`和OpenClaw真实配置不提交Git。
- n8n凭证只保存在Credential Store，并由N8N_ENCRYPTION_KEY保护。
- 日志必须脱敏，不输出完整Token、Cookie、手机号、客户代码和模型请求原文。
- 密钥轮换后重新运行端到端测试。
- 备份中的密钥必须加密或单独离线保存。

## 6. Agent权限

默认允许：读取分配文件、写入本任务目录、运行构建和测试、生成报告。

默认拒绝：浏览器登录、系统全盘读取、支付、发布、消息发送、删除、网络代理设置、SSH密钥、浏览器资料和密码库。

主会话虽然可拥有更多权限，也不得用于处理不可信客户输入。客户输入必须派发到沙箱Agent。

## 7. 人工审批协议

批准文件至少包含：产物相对路径、SHA256、审批人、时间、结论和备注。产物任何字节变化都会使批准失效。超时、无响应和工作流成功均不能被解释为批准。

## 8. 软件供应链

- 运行第三方脚本前阅读全部文件。
- 记录Tag、Commit、镜像Digest和许可证。
- 不执行来源不明的PowerShell、curl pipe shell或二进制。
- 镜像先扫描，再进入正式Compose。
- 依赖更新使用单独PR和回滚测试。

## 9. 内容与版权

技术产品和视频有两层权利检查：代码许可证和素材许可证。MIT等代码许可证不代表网上找到的图片、音乐和视频也可商用。所有交付包必须包含第三方清单，并排除公司/客户机密。

## 10. 事件响应

发现密钥泄漏、异常公网端口、客户目录交叉、可疑Skill或未授权发布时：立即停止相关容器和工作流；保留日志；轮换密钥；隔离产物；确认影响范围；修复后重新执行P0验收。
