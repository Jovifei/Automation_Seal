# Jovi Automation 部署执行总说明

版本：V1.0  
日期：2026-07-11

## 1. 执行摘要

本项目将产品调研、规格管理、软件开发、文档、内容草稿和人工审核串成一条本地优先流水线。OpenClaw负责常驻Agent与调度，n8n负责确定性工作流，Codex负责工程实现与审查，Spec Kit负责把PRD转成可追踪的规格和任务。

第一版部署不追求完全无人化，而追求“无人值守生产、有人负责承诺”。系统可以在夜间完成抓取、分析、测试和打包，但发布、客户沟通和交付始终由用户批准。

## 2. 范围

### 2.1 包含

- 核心服务部署与健康检查。
- GitHub项目版本锁定和许可证登记。
- OpenClaw工作区与9个专用Skill。
- Codex仓库级`.agents/skills/`与OpenClaw `workspace/skills/`双镜像。
- n8n工作流规格和人工审批闸门。
- 第一个嵌入式MVP的Spec Kit开发路径。
- 可选的视频生产模块。
- 备份、恢复、升级和故障处理。

### 2.2 不包含

- 自动控制闲鱼或其他平台账号。
- 自动支付、退款、报价和交付。
- 破解软件、课程搬运或无授权素材销售。
- 任何风控绕过、验证码自动化或批量养号。

## 3. 目标架构

| 层级 | 组件 | 责任 | 部署方式 |
|---|---|---|---|
| 决策与开发 | Codex | 调研、计划、编码、测试、文档 | 用户已有Codex环境 |
| 常驻调度 | OpenClaw | Agent、Cron、会话和Skill路由 | 主机/WSL守护进程 |
| 工作流 | n8n | 定时、队列、审批和日志 | Docker |
| 数据 | PostgreSQL | 工作流和业务元数据 | Docker |
| 页面监控 | changedetection.io | 竞品、规则、Release变更 | Docker |
| 热点雷达 | TrendRadar | 关键词和公开信息聚合 | 独立上游Compose，可选 |
| 规格管理 | Spec Kit | constitution/spec/plan/tasks | uv工具 |
| 文档 | MkDocs | 产品文档网站和离线HTML | 构建工具 |
| 视频 | MoneyPrinterTurbo | 视频草稿和字幕 | 独立GPU模块，可选 |

## 4. 阶段门

| Gate | 通过条件 | 失败处理 |
|---|---|---|
| G0 环境 | WSL2、Docker、磁盘和端口通过 | 不安装，输出修复清单 |
| G1 安全 | 本地绑定、密钥策略和目录隔离通过 | 阻止启动 |
| G2 核心 | n8n、数据库和页面监控健康 | 回滚Compose |
| G3 Agent | OpenClaw doctor通过、非主沙箱启用 | 禁止接入消息渠道 |
| G4 自动化 | 审批闸门和测试工作流通过 | 保持工作流禁用 |
| G5 产品 | P0测试、许可证、文档和包校验通过 | 进入quarantine |
| G6 运营 | 备份恢复与故障演练通过 | 不进入长期运行 |

## 5. 实施顺序

1. 只读预检和版本锁定。
2. 生成本地密钥，人工复核环境变量。
3. 启动核心Docker服务。
4. 安装OpenClaw、Spec Kit和Skill。
5. 实现并验证n8n工作流。
6. 完成E01主机侧MVP。
7. 再接入TrendRadar和视频模块。
8. 进行备份恢复、权限和人工审批测试。

## 6. 运作模型

每个任务都必须产生一个Job Manifest，记录输入、来源、权限、输出、测试和审批状态。Agent只能把产物放入`review-queue`。只有人工批准文件中的SHA256与产物一致时，工作流才能复制到`approved`。

## 7. 主要成功指标

- 核心服务可用性达到本地个人使用要求。
- P0验收通过率100%。
- 研究报告事实来源覆盖率100%。
- 未授权外部动作次数为0。
- 密钥泄漏次数为0。
- 不同客户目录交叉访问次数为0。
- 产品构建可在干净环境重复执行。

## 8. 用户需要提供的信息

部署可先进行到本地核心服务。进入硬件和外部通知前，需要确认：目标MCU/板卡/工具链、通知渠道和备份目的地。
