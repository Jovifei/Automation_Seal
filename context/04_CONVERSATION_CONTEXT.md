# 对话上下文与决策摘要

这份文件是Codex的项目记忆，不依赖原始聊天记录。

## 1. 用户目标

用户希望家中电脑在无人持续控制时，由Codex承担调研、开发、测试、文档和内容草稿等工作，以更快形成可销售的数字产品和技术服务。目标不是未经监管的“自动赚钱机器人”，而是让重复劳动自动化，同时保留真实交易和承诺的人工控制。

## 2. 用户优势

用户是工程师，主要产品优势在嵌入式领域，包含STM32/GD32、FreeRTOS、Modbus、4G、MQTT、OTA、Bootloader、HardFault和状态机等。摄影是第二产品线，重点为用户自己拥有版权的照片、预设、RAW练习和机位指南。

## 3. 渠道结论

- 嵌入式：B站建立技术信任，闲鱼承接低价产品和技术服务，抖音展示故障修复，小红书承载搜索型图文；微博只同步。
- 摄影：小红书和抖音优先，B站做完整教程，闲鱼只承接原创预设和服务。
- 不应把两个方向混在同一个垂直账号中。

## 4. 产品结论

首个产品不是大而全的课程合集，而是：

```text
Modbus RTU诊断与模板工具包
```

优先交付主机侧、可测试、与板卡无关的功能。板级工程等用户明确MCU、开发板、IDE和工具链后再做。

摄影首个候选是金鸡湖城市风光调色与机位工具包，但缺少用户原创素材时不阻塞嵌入式主线。

## 5. 资源和版权边界

不得销售：

- 未经授权的网络课程、电子书和资料包；
- 破解软件、激活工具、共享账号；
- 他人的预设、LUT、字体、模板；
- 公司、雇主、客户或学校的代码和内部资料；
- 权利不明的GitHub源码合集。

可以销售：

- 用户原创课程、代码、脚本、工具和摄影资产；
- 明确获得商业授权的资源；
- 按开源许可证合规使用并提供声明的组件；
- 官方免费软件的配置、培训和支持服务。

## 6. GitHub与自动化路线结论

经过多轮复核，采用以下分层：

- Codex：核心本地执行和开发；
- 项目级AGENTS、Skill、Hook：执行规则和安全边界；
- 轻量变更记录：日常小改动；
- Spec Kit：较大的产品级规格；
- n8n：后续确定性工作流，不阻塞Alpha；
- changedetection.io：公开页面和规则变化；
- Promptfoo：AI回复合成评测；
- Gitleaks/Trivy：密钥和供应链安全；
- PlatformIO、Ceedling、Unity、Renode：嵌入式构建和测试增强；
- Docling/PaperQA2：有权处理的文档和文献密集研究；
- OpenClaw、Langfuse、视频生成工具：后续按真实需求启用。

不同时安装多套重叠的总控框架。OpenSpec、BMAD和Superpowers主要作为方法论参考。

## 7. 现有闲鱼工程

用户已经在本地部署：

```text
GitHub: GuDong2003/xianyu-auto-reply-fix
路径: E:\project\xianyu-auto-reply
技术栈: FastAPI + SQLite + Playwright/DrissionPage + Docker Compose
```

它包含关键词回复、AI回复、自动发货、商品和订单管理等能力。

最终决定：不重做、不合并数据库，而是把它作为独立执行适配器。Jovi Automation初期只生成候选文件，由用户审核和人工导入。

## 8. 风险结论

- 上游闲鱼项目是AGPL-3.0，同时README有学习研究提示，商业使用边界必须澄清；
- 默认Compose可能存在弱凭据、root、读写挂载、VNC和非本机端口，但必须以本地事实为准；
- 不实现验证码、滑块、人脸、指纹或风控绕过；
- 真实AI回复、发货、改价、退款都不由Codex直接启用；
- 每个写阶段都需要绑定计划SHA256的用户批准。

## 9. 最终交付预期

用户下载一个ZIP，解压后把目录交给Codex。Codex应读取本包而不是询问已经解决的问题，也不应重新进行广泛调研。它只需要：

1. 验证目标机事实；
2. 验证少数易变版本和安全信息；
3. 审计现有闲鱼本地实例；
4. 按Track P/Track I和X0-X4阶段执行；
5. 每个阶段输出证据并停止等待批准。
