| 建议立项：采用“双产品线、两阶段验证”策略：嵌入式线优先销售可编译模板、诊断工具与技术服务；摄影线优先销售原创预设、练习RAW、机位指南与点评服务。严禁把未经授权的网课、破解软件、账号或他人素材作为商品。 |

# 3. 项目边界
允许：原创课程、原创代码、原创文档、原创照片与预设、取得商业授权的素材、合规使用的开源组件、技术咨询与适配服务。
谨慎：使用公司任职期间完成的代码、使用客户工程、引用第三方源码、使用免费字体/照片/音乐、提供远程调试。必须先确认权利与许可证。
禁止：盗版网课、破解软件、激活工具、共享账号、未经许可的源码/电子书/插件/预设、绕平台风控、自动批量私信、虚假宣传和无法验证的“永久更新”。
# 4. 标准阶段门
| 阶段门 | 要完成的工作 | 通过条件 |
| --- | --- | --- |
| G0 立项 | 确认时间预算、产品线和合规红线 | 每周可投入≥8小时；不依赖盗版资源 |
| G1 问题验证 | 完成用户访谈和竞品抽样 | 每条产品线至少10名合格访谈；≥60%确认真实痛点 |
| G2 付费验证 | 用预售或小规模服务验证价格 | 至少5个真实付费订单或明确拒绝原因 |
| G3 MVP验收 | 产品可用、可交付、可支持 | 验收项100%通过；无高风险版权缺口 |
| G4 上线 | 完成商品页、内容、客服和交付SOP | 支付、交付、退款、版本记录均可追溯 |
| G5 扩张 | 复制有效渠道和产品 | 连续4周贡献毛利为正，售后时间可控 |

# 6. 每周使用方式
周一：打开执行看板，确认本周唯一最高优先级结果。
周三：检查访谈、开发、内容和合规阻塞项。
周五：更新KPI、实验结果、收入成本和风险登记。
周日：根据DOC-07的决策规则决定继续、调整、暂停或下架。
