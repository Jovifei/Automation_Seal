# 4. 商品页标准结构
标题：目标用户＋具体问题＋产品形态＋明确版本，不使用“全网最全/永久更新/百分百解决”。
首屏：3句话说明适合谁、解决什么、不适合谁。
证据：编译/测试截图、真实前后对比、版本和更新时间。
交付：目录、文件格式、获取方式和预计大小。
兼容：芯片、IDE、软件、相机和操作系统。
授权：个人使用、禁止转售、第三方依赖。
售后：免费范围、时限、需要提供的信息、付费诊断边界。
退款：按照平台和法律要求执行，数字内容交付状态和使用情况需可证明。

# 6. 咨询与报价SOP
| 步骤 | 动作 | 标准 |
| --- | --- | --- |
| 1 筛选 | 确认目标、环境、截止时间和预算 | 不接描述不清且要求包成功的项目 |
| 2 收集 | 使用标准表收集版本、日志、最小复现 | 不先收完整公司工程 |
| 3 评估 | 给出是否能做、范围、交付、价格和不确定性 | 重要承诺写在平台聊天中 |
| 4 付款 | 按平台交易，不引导站外 | 确认订单与范围 |
| 5 执行 | 独立客户目录、版本控制、记录修改 | 不访问无关文件和账号 |
| 6 交付 | 压缩包+报告+测试+哈希+授权 | 客户确认收到 |
| 7 售后 | 只处理原范围缺陷；新增需求重新报价 | 关闭条件明确 |
