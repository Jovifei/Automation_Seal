# 1. 产品背景
Modbus资料很多，但用户常遇到版本不一致、帧长度理解错误、收发超时、RS485方向控制、CRC、寄存器映射和FreeRTOS并发等问题。用户需要的不是更多资料，而是一套可以直接验证、定位和集成的工具链。
# 2. 产品目标与非目标
| 类型 | 内容 |
| --- | --- |
| 目标 | 让目标用户在30分钟内完成报文解析，在2小时内跑通指定板卡的从站示例，并能按故障树定位80%的常见问题。 |
| 业务目标 | 上线30天获得10个付费订单；退款/争议<10%；平均售后≤20分钟/单。 |
| 非目标 | 不覆盖所有MCU、所有编译器、所有Modbus扩展；不承诺解决客户完整项目；不包含未经授权的商业协议栈。 |

# 3. 目标用户
| 用户 | 场景 | 核心任务 |
| --- | --- | --- |
| 初学者 | 学习STM32/GD32与Modbus | 理解帧、跑通例程、修改寄存器 |
| 项目工程师 | 设备联调/现场故障 | 快速判断主从、超时、CRC、方向、映射问题 |
| 小团队负责人 | 代码复核与交付 | 获得规范、测试和风险清单 |

# 4. 用户故事
作为初学者，我希望输入一帧十六进制数据就得到字段解释和错误提示，以便理解请求与响应。
作为工程师，我希望用测试脚本模拟主站/从站，以便排除上位机和设备端哪一侧有问题。
作为项目负责人，我希望看到兼容版本、测试结果和已知限制，以便决定是否集成。
作为购买者，我希望在购买前明确支持的芯片、IDE和售后范围，避免交付争议。

# 6. 功能需求

# 8. 关键流程
用户查看商品页兼容范围→选择个人版/工程版/含诊断版。
交付压缩包、SHA256、版本说明和授权文件。
用户按QuickStart安装环境→运行帧分析器→跑测试脚本→烧录示例。
出现问题时先执行自检清单；仍未解决则提交最小日志和环境信息。
超出支持范围时给出付费诊断报价，不在聊天中无限扩展需求。
