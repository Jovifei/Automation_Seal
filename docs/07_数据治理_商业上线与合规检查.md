# 数据治理、C4 商业试点与合规检查

**最后校准：2026-09-05**

## 1. 数据分类

| 分类 | 示例 | 当前规则 |
|---|---|---|
| 公开证据 | 官方文档、公开 README、平台公开规则 | 可保存来源与时间 |
| 原创产品 | Modbus 产品源码、文档、installer/ZIP | 产品仓为字节权威，Commerce 只读引用 |
| 第三方组件 | Medusa、依赖、打包工具 | pin 版本/commit、license、NOTICE、SBOM |
| Commerce 运行数据 | synthetic/real pilot order、Entitlement、Receipt | 最小化、可审计 |
| 买家敏感数据 | 姓名、电话、地址、完整聊天、支付凭据 | C4 不进入 Runtime/GitHub |
| 平台秘密 | Cookie、Token、Browser Profile | 仅外部适配器/本地秘密域，不进入本项目 |
| 工程秘密 | API Key、密码、salt/HMAC key | 不进 Git/报告/聊天 |

## 2. 第一 SKU 权利与供应链状态

C3 已 reported 验证：
- 产品仓 read-only/zero-write；
- 产品构件 SHA 绑定；
- product tests；
- license/third-party evidence；
- deterministic Commerce wrapper；
- C3 independent audit PASS。

真实 Pilot 前仍需现场重算原始 C3 evidence，而不是只相信 governance mirror。

## 3. Listing Claim 合规

C4 发布文案必须满足：

`claim -> C3 claim_id -> evidence_path -> evidence_sha256 -> KEEP/REWRITE/REMOVE`

禁止：
- “全设备兼容”“100%兼容”；
- 无证据的 Windows/Python 范围；
- 无证据的运行时间承诺；
- 把 CRC 写成“纠错”；
- 把 SHA256 写成“数字签名”；
- 无证据声称交付源码/PDF/工具/模拟器；
- “永久更新”“包教会”“保证解决全部问题”等无限承诺。

## 4. C4 数据最小化

首轮 Pilot 继续保持 `real_customer=false`，含义是 Runtime 不持久化原始客户身份/Profile。

推荐每单只记录：
- `pilot_order_id`；
- 随机内部引用或 keyed HMAC 的 platform reference；
- product/release/version；
- listing candidate SHA；
- Jovi 人工付款确认事实；
- Entitlement ID；
- Package SHA；
- DeliveryReceipt ID；
- Jovi 人工交付确认；
- support/refund 分类。

不保存：
- 真实姓名、手机号、地址；
- 闲鱼 Cookie/Token/Profile；
- 完整私聊；
- 银行/卡号/支付凭证明文；
- 不必要的截图。

## 5. 平台规则检查

C4 Human Decision 签发前必须重新核验当前公开规则：
- 闲鱼数字/虚拟商品类目和交付要求；
- 当前退款/争议规则；
- 商品描述和售后承诺边界；
- 自动化/浏览器行为账号风险；
- 税务/发票/经营主体要求（如适用）。

旧文档或旧平台经验不能替代 2026-09 当前规则。

## 6. 当前产品商业透明度

当前 reported：
- version：`0.2.0-dev`；
- installer：`UNSIGNED`。

Jovi 在 C4 前必须选择：

### Beta Pilot
透明说明 beta/dev/unsigned、适用人群和已验证范围。

### Stable First
先在产品仓独立完成 stable/signing/release notes，然后重新做必要资格化与 Commerce delta audit。

Agent 不得自行把 dev 改称正式版，也不能声称 SmartScreen/Authenticode 保证。

## 7. 退款与售后

不要写绝对化“数字商品发货后一律不退款”，除非当前平台规则和适用法律/业务条件明确支持。

首轮 Pilot 推荐：
- 购买前人工确认环境与需求；
- 兼容/交付问题人工处理；
- refund/dispute 由 Jovi 决定并记录分类；
- 不让模型自动承诺补偿、价格或退款结果。

## 8. OSS/供应链

当前已采用：
- Medusa v2.19.0；
- Playwright；
- Gitleaks v8.24.0；
- Syft v1.20.0；
- Redis/PostgreSQL/Docker。

选择性参考：
- MakePay digital-downloads（immutable release/private asset/DownloadGrant）；
- PyInstaller / Inno Setup 产品打包模式。

C4 前不需要引入 n8n production、SLSA/cosign、Storefront、S3 或新 Commerce framework。

## 9. 停止条件

出现任一情况停止真实 Pilot：
- 商品 claim 无法回绑 evidence；
- package SHA 漂移；
- wrong-version delivery；
- duplicate Entitlement/Receipt；
- unauthorized platform action；
- 买家 PII 被 Runtime/Git 意外保存；
- 当前平台规则与计划冲突；
- 产品 source/release 发生未经资格化的变化；
- Jovi 无法确认付款/争议事实。

## 10. 商业 V1 完成标准

- C4 Human Decision 正式签发；
- 5–10 单或固定时间窗真实证据；
- 0 duplicate / wrong-version / unauthorized action；
- package/release/payment fact 可追溯；
- 人工耗时、support、退款/未成交原因有统计；
- C4 结束于 `C4_HUMAN_PILOT_PASS_PENDING_PERMISSION_DECISION`；
- 后续权限逐动作另行决定，不全局开放。
