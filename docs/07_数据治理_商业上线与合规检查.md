# 1. 数据分类

| 分类 | 示例 | 存储规则 |
|---|---|---|
| 公开证据 | 官方文档、公开README、公开价格 | 可进入research目录并保留来源 |
| 原创产品 | 用户代码、文档、照片、预设 | 独立产品目录和权利登记 |
| 第三方组件 | 开源库、字体、主题、SDK | 记录版本、许可证和NOTICE |
| 用户敏感数据 | Cookie、买家消息、订单、卡密 | 不进入Jovi工程和报告 |
| 秘密 | API Key、密码、加密密钥 | 仅秘密存储，不进入Git |
| 客户资料 | 客户代码、日志、原理图 | 客户隔离、最小保留、按约删除 |

# 2. 产品上线前权利检查

每个SKU必须回答：

1. 所有源代码是否原创或有明确许可证；
2. 所有图片、RAW、预设、字体和音乐是否有商业使用权；
3. 是否包含雇主、客户或学校的职务资料；
4. 是否需要保留版权声明、提供源码或相同许可证；
5. 商品描述是否准确说明兼容范围；
6. 是否存在不能验证的效果或收益承诺。

权利状态只能是：

```text
ORIGINAL
VERIFIED_LICENSE
BLOCKED
```

`PENDING`和`BLOCKED`不得进入approved。

# 3. 软件供应链

正式产品包至少包含：

```text
SHA256SUMS.txt
SBOM.cdx.json
THIRD_PARTY_NOTICES.md
LICENSE.txt
BUILD_PROVENANCE.json
TEST_REPORT.md
```

初期使用SHA256和CycloneDX SBOM。稳定发布后再评估Cosign签名。

# 4. 闲鱼商业上线检查

真实上线前必须重新核验：

- 当前平台协议和类目；
- 数字商品、技术服务和自动发货规则；
- 退款、售后和争议处理；
- 是否需要发票、税务登记或经营资质；
- 上游闲鱼系统AGPL和README使用提示；
- 自动回复和浏览器自动化是否会增加账号风险。

未核验时只能生成草稿，不能自动启用。

# 5. 用户告知与售后

商品页至少说明：

- 产品版本和交付内容；
- 支持的芯片、软件和场景；
- 不支持范围；
- 购买前沟通要求；
- 是否提供源代码；
- 售后时长；
- 退款和问题处理规则；
- AI仅辅助、最终结果需人工验证。

# 6. 数据保留

建议默认：

- 公开研究证据：长期保留来源；
- 产品构建日志：至少保留一个发布周期；
- 审批回执：与产品版本同寿命；
- 客户代码和日志：项目完成后按约删除；
- 闲鱼Cookie和浏览器状态：只保存在闲鱼工程；
- 备份：加密、离线副本、定期恢复演练。

# 7. 重大风险停止条件

出现以下任一情况立即停止上线：

- 权利来源不清；
- 扫描发现密钥或客户数据；
- 产品测试无法复现；
- 商品描述超过实际能力；
- 平台规则或许可证边界不明确；
- 自动回复或交付出现误操作；
- 没有可验证的回滚和备份。

# 8. 商业上线完成标准

- 有真实目标用户证据；
- 产品包可重复构建；
- 权利、许可证和SBOM完整；
- 商品页和售后边界明确；
- 支付、退款和争议由用户控制；
- 紧急停止演练完成；
- 真实平台动作逐SKU启用，而不是全局打开。
