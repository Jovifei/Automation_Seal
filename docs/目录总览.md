## 0. 为什么是「索引 + 分类视图」而非物理挪动

为**不破坏既有引用**，原始文档（`docs/00`–`docs/08` 及两个交付包 ZIP）**保持原位**。下列文件按当前路径硬引用了这些文档，移动会直接导致失败：

- `scripts/validate-package.py` —— 包校验脚本，硬编码检查 `docs/00_…` 与 `docs/08_…` 存在（项目硬门禁之一）。
- `context/01_REQUIREMENTS_TRACEABILITY.md` —— 需求追溯，引用 `docs/03_…`、`docs/05_…`。
- `prompts/20_track_i_core.txt` —— 引用 `docs/05_…`。
- `MANIFEST.txt` / `MANIFEST.sha256` —— 冻结清单，按当前路径登记。

因此本索引与 `docs/0X-*/README.md` 分类视图**仅作检索用途**。如需把文件物理归并到子目录，须作为受管变更另行更新上述引用与 `MANIFEST`（含重新生成 `MANIFEST.sha256`）。

## 2. 工具受管目录（⚠️ 请勿移动 / 重命名）

以下目录由 comet / OpenSpec / Superpowers 工具管理，路径写死在 `.comet.yaml` 等状态文件中，移动会破坏工具状态：

- `docs/openspec/` —— OpenSpec 配置与变更归档（`config.yaml`、`specs/`、`changes/archive/`）。
- `docs/superpowers/` —— Superpowers 设计文档 / 计划 / 报告（`specs/`、`plans/`、`reports/`）。

归档示例（Route B 受控 APPLY 载体，已 `archived=true`，未真实写入）：
`docs/openspec/changes/archive/2026-08-06-route-b-qualification-controlled-apply/`

## 3. 命名规范建议（供后续新增文档参考）

- 交付物文档沿用 `NN_主题_副标题.扩展名`（NN = 00–08 序号，保持时序）。
- 分类视图子目录采用 `NN-英文类别/` 形式（如 `01-PRD/`），便于按软件生命周期排序。
- 新增专题文档建议前缀：
  - `prd-<topic>-<YYYY-MM-DD>.md`
  - `arch-<topic>-<date>.md`
  - `coding-<topic>-<date>.md`
  - `test-<topic>-<date>.md`
  - `plan-<topic>-<date>.md`
  - `deliverable-<topic>-<date>.md`

## 4. 快速检索

- 想看**全部文档地图** → 本文件。

- 想看**归档的变更/规格/计划/报告** → 见第 2 节工具受管目录。
