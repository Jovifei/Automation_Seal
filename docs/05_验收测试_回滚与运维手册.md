## 3. C4 Pre-Publish P0

在真实 Pilot 前必须：

- C3 原始 audit/report/sidecar 现场复核；
- Runtime main 与 audited C3 closure 一致；
- C4 Listing 每条技术 claim 绑定 C3 evidence；
- Pilot ledger 从 0 条真实记录开始；
- `0.2.0-dev` / unsigned 状态透明；
- 当前闲鱼数字/虚拟商品与退款规则重新核验；
- DeliveryPackage SHA 复核；
- 人工交付通道冻结；
- six real-action flags 仍 false；
- C4 Human Decision 必须 `issued_from_human=true`。

## 4. C4 Pilot 每单 P0

每个真实订单至少验证：

1. Jovi 人工确认真实付款事实；
2. order/product/version 正确；
3. Entitlement 只生成 1 个；
4. DeliveryReceipt 只生成 1 个；
5. 交付 Package SHA 与 C3 Release 一致；
6. Jovi 手工发送；
7. 无自动闲鱼写动作；
8. 无原始客户 PII 进入 Runtime；
9. support/refund 只保存最小分类；
10. 发生失败时可以停止并恢复。

## 5. Pilot 批次退出标准

至少：
- duplicate Entitlement = 0；
- duplicate Receipt = 0；
- wrong-version delivery = 0；
- unauthorized platform action = 0；
- package traceability = 100%；
- payment confirmation 可回溯到 order；
- 人工分钟/单、support 分类、退款/未成交原因有记录。

目标状态：

`C4_HUMAN_PILOT_PASS_PENDING_PERMISSION_DECISION`

Pilot PASS 也不自动开放新权限。

## 6. 回滚

### Governance 文档
- PR 变更发现误导/错误时不 merge；
- 历史 audit 原件不覆盖；
- mirror 可修文本，但必须明确其不是原始 evidence。

### Runtime
- 当前正式主线必须是经过 promotion audit 的 C3 closure；
- Pilot 前若出现 Runtime 代码新改动，创建新 feature + tests + independent audit，不在 main 临时修；
- 不使用 `reset --hard`/`clean` 清理未知用户工作。

### 产品仓
- Commerce 不修改产品源；
- 产品自身问题进入独立产品修复分支；
- 修复后重新做 product qualification/C3 delta audit；
- 不为了 Commerce 快速通过而重建原始 installer/ZIP。

### Pilot
出现错版本、重复权益、付款争议、隐私或平台异常：
- 停止新订单处理；
- Jovi 停止人工发布/发货；
- 保存脱敏证据；
- 不删除数据库/日志来制造“干净”；
- 根因修复后重新验证。

## 7. 当前运维

C4 首轮不要求无人值守生产运行。最低运维要求：
- Runtime 本机服务可健康启动/恢复；
- PostgreSQL/Redis 数据不因重启丢失；
- 磁盘空间足够保留 evidence/package；
- Gitleaks/Syft 可复跑；
- package SHA 在发货前人工复核；
- 客户资料最小化。

n8n production、changedetection、S3、Storefront、远程运维等均为未来项，不是 C4 P0。

不能把 synthetic/C3 PASS 描述为“已经商业上线”。
