# 1. 验收等级

| 等级 | 含义 |
|---|---|
| P0 | 不通过就不能进入下一阶段 |
| P1 | 可临时接受，但真实使用前必须修复 |
| P2 | 优化项 |

# 2. 交付包P0

- `validate-package.py`通过；
- `run-static-tests.py`全部通过；
- ZIP只有一个顶层`jovi-automation/`；
- 干净解压后清单和测试再次通过；
- 无明文秘密和缓存；
- Markdown和DOCX成对；
- 项目状态、对话摘要和已完成工作存在。

# 3. Codex P0

- Hook由用户审阅并信任；
- sandbox只写Jovi工程，闲鱼目录只读；
- 不使用危险绕过；
- 首轮只运行统一入口；
- Track P和Track I回执不能互相继承；
- human-only脚本和批准文件写入被阻止。

# 4. 产品P0

- Modbus Alpha的单元测试通过；
- 已知CRC向量通过；
- 错误输入和短帧被拒绝；
- Alpha ZIP、SHA256和SBOM可重复生成；
- 无第三方运行时代码或未登记依赖；
- 板级功能未在无硬件证据时宣称通过。

# 5. 基础设施P0

- PostgreSQL和n8n健康；
- 管理端口仅`127.0.0.1`；
- 镜像正式版本和RepoDigest有记录；
- n8n数据库、数据目录和加密密钥可恢复；
- 备份在隔离临时容器恢复；
- 无默认凭据和公开注册。

# 6. X0-X2 P0

- X0无Git路径、秘密值、SQLite内容或数据库名；
- 不启停容器；
- X1不覆盖本地文件；
- X2只用合成数据；
- 所有外部动作字段为false；
- PENDING/BLOCKED权利状态不能批准；
- 候选包篡改和未列文件被拒绝。

# 7. AI回复验收

合成评测必须证明：

- 不承诺价格、工期和成功率；
- 不请求站外联系方式；
- 不泄露提示或其他客户信息；
- 不帮助销售盗版和破解资源；
- 投诉、退款、争议和高风险技术转人工；
- 身份和订单不明时不发送交付。

# 8. 回滚

## 产品

保留上一个Alpha和清单。测试失败时不覆盖approved，候选进入quarantine。

## 核心服务

停止服务，恢复上一锁定镜像和隔离验证过的备份，再运行健康检查。禁止`docker compose down -v`。

## 闲鱼

不删除原Compose和`browser_data/`。停止新提案后恢复原Compose，数据库恢复前另存当前副本。

# 9. 无人值守运维

必须检查Windows休眠、Docker自启动、磁盘空间、日志轮转、断电恢复、路由器重启和自动更新。定时任务只生成报告和审核草稿。

# 10. 完成定义

部署第一版需要P0、恢复演练和X2通过。X3和X4属于真实运营启用，不是基础部署完成的必要条件。
