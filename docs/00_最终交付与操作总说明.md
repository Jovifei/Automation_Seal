# 执行摘要

Jovi Automation V3.0是可以直接交给Codex的完整工程，不是单纯文档集合。它使用“结构化上下文保存决策、脚本作为唯一入口、测试作为证据、用户回执作为权限”的方式，让Codex在不依赖当前聊天的情况下继续执行。

最终决策：保留`E:\project\xianyu-auto-reply`作为独立闲鱼执行适配器；Jovi Automation不复制其数据库、不接管Cookie、不平行重做后台。

# 1. 用户从零开始的操作

## 1.1 校验和解压

校验ZIP旁的SHA256文件，然后解压到：

```text
E:\project\jovi-automation
```

两个工程应并列：

```text
E:\project\
├── jovi-automation\
└── xianyu-auto-reply\
```

## 1.2 备份闲鱼工程

在任何变更前备份数据库、配置、浏览器状态、Compose和Git状态。秘密和用户数据不能进入Jovi工程或聊天。

## 1.3 打开Codex

将`E:\project\jovi-automation`作为工程根目录。审阅并信任项目Hook，必要时给闲鱼目录增加只读根。

## 1.4 发送固定指令

复制`CODEX_START_PROMPT.txt`全文。Codex第一次只运行：

```powershell
.\scripts\00-run-readonly-audit.ps1 `
  -XianyuRepoPath 'E:\project\xianyu-auto-reply'
```

## 1.5 审阅并批准

第一次执行结束后查看：

```text
reports/package-static-tests/
reports/phase-a/
reports/xianyu/x0/
reports/gates/GATE_A_PLAN.json
STATUS.md
```

推荐先只批准Track P。批准Track I是独立决定。

# 4. 为什么不能一次性全自动

闲鱼工程包含登录状态、订单、买家消息、自动回复、发货和浏览器自动化。让Codex直接获得整个目录和真实执行权，会同时扩大隐私、账号、平台、许可证和交易风险。

本工程把“产生候选内容”和“执行真实交易”分成两个信任域。每个写阶段需要绑定计划SHA256和轨道的用户回执；文件变化后旧批准失效。

# 5. Codex阶段输出

- 计划和SHA256；
- 执行命令和变更；
- 测试和负向测试；
- 安全、许可证和隐私；
- 回滚方法；
- 证据路径；
- 更新后的状态；
- 下一阶段停止点。

# 6. 用户不可交给Codex的内容

- Cookie、浏览器Profile和闲鱼管理员密码；
- 买家消息、订单隐私和卡密；
- 支付、退款和API秘密；
- 公司、客户和雇主代码；
- 未授权课程、软件和摄影素材。
