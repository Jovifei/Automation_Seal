# 1. 总体架构

```text
冻结研究与真实用户证据
  ↓
PRD / 轻量变更规格
  ↓
Codex产品构建与测试
  ↓
许可证、密钥、SBOM和质量检查
  ↓
review-queue
  ↓
用户SHA256批准
  ↓
approved
  ↓
用户人工导入闲鱼执行适配器
```

# 2. 信任域

| 信任域 | 可以访问 | 不可以访问 |
|---|---|---|
| Jovi控制平面 | PRD、公开资料、产品源码、报告 | 闲鱼Cookie和买家数据 |
| 产品构建平面 | 单个产品、测试和合成数据 | 其他客户和其他产品秘密 |
| 审核平面 | 候选产物、清单、哈希 | 平台账号操作 |
| 闲鱼执行适配器 | 自己的数据库、Profile和会话 | Jovi研发秘密 |
| 秘密存储 | API Key、密码和加密密钥 | Git、报告和聊天 |

# 3. Track P与Track I

Track P处理产品目录、测试、文档和内测材料；Track I处理Docker和基础设施。两个轨道分别批准，一个回执不能继承另一个权限。

# 4. Codex安全

- 使用workspace-write或更严格sandbox；
- 闲鱼目录只增加读取根；
- Hook阻止human-only脚本、批准文件写入、Xianyu修改、平台动作、危险删除和验证处理；
- Hook不能替代AGENTS、用户审批和最终审查；
- 不使用任何sandbox、approval或Hook信任绕过。

# 5. 数据生命周期

```text
sources            冻结公开证据
reports            新生成的事实和测试
products           原创产品源码
review-queue       待审核草稿
approved           哈希批准产物
quarantine         权利、安全或质量失败
backups            加密备份
```

# 6. 密钥和隐私

- `.env`不进入Git；
- n8n数据库、数据目录和加密密钥必须成组备份；
- 闲鱼秘密不进入Jovi工程；
- X0不输出Git变更路径，不打开或哈希SQLite，不输出配置值；
- 产品发版前运行Gitleaks和人工隐私检查。

# 7. 网络

- 管理端口只绑定`127.0.0.1`；
- 不默认开启Nginx、公网Webhook或远程桌面；
- 远程访问必须另做威胁建模；
- VNC、noVNC、远程滑块和后备验证默认关闭。

# 8. 备份与恢复

核心备份包括PostgreSQL、n8n数据目录、加密密钥、changedetection数据、Jovi工作区、版本锁和批准回执。恢复必须在隔离临时环境验证。

闲鱼备份独立完成，不进入Jovi备份目录，不删除`browser_data/`。

# 9. 供应链

正式产品至少包含SHA256、SBOM、THIRD_PARTY_NOTICES、LICENSE、构建来源和测试报告。容器正式部署必须记录RepoDigest。
