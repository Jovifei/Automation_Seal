# n8n：仅内部编排

**核验日期：2026-08-30；结论：`DIRECT_REUSE_INTERNAL_ORCHESTRATION`。**

## 官方身份与审查锚点

- 官方仓库：[n8n-io/n8n](https://github.com/n8n-io/n8n)；官方文档：[docs.n8n.io](https://docs.n8n.io/)。
- 审查锚点：`n8n@2.36.8`（官方 release tag；部署前须解析 tag 对应提交和镜像 digest）。
- 许可证：Sustainable Use License 1.0（source-available/fair-code，非 OSI 开源）；`.ee` 文件与企业组件另受企业许可约束。

## 技术栈与直接复用

n8n 是 Node.js/TypeScript 工作流自动化平台，提供节点、webhook、队列/执行记录、凭证加密和自托管部署能力。可直接复用仅是**内部**的确定性触发、审核队列、定时任务、失败重试通知和证据归档编排。每个工作流必须最小权限、显式输入输出 schema、幂等键和人工闸门。

## 借鉴但不采用

借鉴节点封装、运行记录、错误工作流与可视化编排；不采用客户可创建/连接工作流的托管模式、未审查 community node、自动支付、自动发货、自动消息、自动改价、自动退款、浏览器凭据读取或远程代码节点。不得把 n8n 当作 secrets vault 或不可审计的业务规则引擎。

## 与本工程的关系

`jovi-automation` 是控制平面；n8n 是 Track I 的潜在内部执行器，只有独立 Gate 才能部署。Medusa 只能以最小权限 service account 投递已验证事件；Python oracle 产物先落为可复算输入，再由固定工作流转成审核项；闲鱼适配器仅接收人工批准文件，n8n 不接管其数据库、Cookie、Token 或真实平台操作。

## 集成成本、许可义务与安全风险

成本包括 PostgreSQL、加密密钥及其恢复演练、备份、队列策略、节点审查、日志脱敏、网络隔离、凭证轮换和失败恢复。Sustainable Use License 仅适合自身内部业务目的或非商业/个人使用；不得将 n8n 的核心功能作为面向客户的收费托管/工作流产品，分发时保留许可与变更通知，并核对 EE 文件。主要风险是 webhook 未鉴权、SSRF、任意代码节点、凭证外泄、表达式注入、错误重试导致重复副作用和工作流导出包含秘密。

## 升级触发条件

安全公告、许可证/EE 边界变化、`2.36.8` 的破坏性变更、Node/PostgreSQL 兼容性、已使用节点或加密/凭证格式变化触发评估。升级必须锁定 release 提供的 SBOM/镜像 digest，验证备份恢复、凭证解密、幂等重放和工作流导入，且不能以测试出口码代替验收。

## 结论枚举

1. `DIRECT_REUSE_INTERNAL_ORCHESTRATION`：仅限内部受控编排。
2. `NOT_OSI_OPEN_SOURCE`：先做许可/商业模式审查。
3. `NO_CUSTOMER_WORKFLOW_HOSTING`：当前不得提供客户自助工作流。
4. `NO_XIANYU_AUTOMATION`：不自动发布、回复、发货或处理验证。
