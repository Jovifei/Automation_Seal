# 闲鱼接入方案 — 当前 C4 Human Pilot 模式

**最后校准：2026-09-05**

## 1. 当前决策

`E:\project\xianyu-auto-reply` 继续作为**独立外部适配器/历史能力来源**，不与 `jovi-medusa-commerce-v1` 合并数据库、Cookie、Token 或浏览器 Profile。

当前 C4 **不启用自动闲鱼动作**。系统只生成候选和内部交付准备；真实平台操作由 Jovi 手工完成。

## 2. 当前 C4 平台操作矩阵

| 动作 | 当前允许方式 |
|---|---|
| 商品文案生成 | 系统生成 evidence-bound candidate |
| 闲鱼发布 | Jovi 手工 |
| 改价 | Jovi 手工 |
| 买家消息/商业承诺 | Jovi 手工 |
| 付款确认 | Jovi 手工核实 |
| Entitlement/Receipt/Package 准备 | Commerce Runtime |
| 最终发送交付物/链接 | Jovi 手工 |
| 退款/争议 | Jovi 手工 |
| 自动读取 Cookie/Token/Profile/SQLite | 禁止 |

C4 Decision Candidate 仍为 `issued_from_human=false` 时，连真实 Pilot 都不得开始。

## 3. Candidate 契约

Listing / Xianyu Draft 必须：

- `candidate_only=true`
- `platform_action_allowed=false`
- `human_review_required=true`

商品文案每一项技术 claim 必须能回绑 C3 原始 claim evidence。无证据的兼容性、性能、耗时、支持范围和售后承诺直接删除，不允许模型自行补全。

## 4. C4 Pilot 的最小平台数据

Runtime 只保留：
- 内部 `pilot_order_id`；
- 脱敏/键控的平台引用；
- 产品/版本；
- Jovi 手工确认的付款事实；
- Entitlement ID；
- DeliveryPackage SHA；
- DeliveryReceipt ID；
- support/refund 分类。

不保存：
- Cookie / Token / Profile；
- 买家真实姓名、手机号、地址；
- 完整聊天；
- 原始支付账号/凭据；
- 外部 SQLite 内容。

## 5. 当前交付方式

首轮 Pilot 不要求自动发货。Jovi 在付款人工确认后：

1. Runtime 准备 Entitlement / Package / Receipt；
2. Jovi 核对 package SHA；
3. Jovi 使用选定的人工传输方式发送；
4. 台账仅记录最小化、脱敏事实。

人工传输渠道（网盘/受控链接等）必须在 Pilot 前单独冻结；不能因为文档列出某个选项就视为已经批准。

## 6. 未来权限扩展

C4 PASS 后才讨论自动化权限，而且必须**逐动作授权**：

1. listing 自动生成/更新；
2. reply suggestion；
3. order metadata import helper；
4. delivery preparation；
5. 自动消息；
6. 自动发货；
7. 自动改价；
8. 自动退款。

高风险动作不能因为低风险能力 PASS 而继承授权。

## 7. 历史 X0-X4 模型

早期文档曾使用 X0-X4：只读审计、加固提案、synthetic 测试、固定回复、单 SKU。该模型的“先 synthetic、后人类批准、平台秘密隔离”思想仍保留，但**阶段编号不再是当前主线**。

当前阶段名称以：

`C2 -> C3 -> C4 Human Pilot -> Permission Expansion Decision`

为准。

## 8. 平台/许可证规则

真实 Pilot 前必须刷新当前闲鱼：
- 数字/虚拟商品类目与交付规则；
- 退款/售后/争议规则；
- 自动化/浏览器行为风险；
- 商业主体/税务/发票要求（若适用）。

`xianyu-auto-reply` 上游许可证或 README 的历史结论不能替代当前平台与许可证核验。

## 9. 风控与停止

本项目不实现验证码、滑块、人脸、设备指纹或平台风控绕过。

出现：误承诺、错版本、付款争议、隐私问题、账号异常时，Jovi 立即停止人工 Pilot，保留脱敏证据，完成原因分析后再恢复。
