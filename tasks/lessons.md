# Lessons

- Treat expected test-generated files as fixtures: snapshot and byte-restore them only inside a fresh owned Shadow, then prove the final tree equals its pre-test snapshot.
- Run audit commands once with direct output capture. A harness setup error or a nonexistent command path is diagnostic evidence, never a reason to rerun a completed test or misclassify the candidate.
- For every non-trivial task, maintain the same factual status in `tasks/todo.md` and the project Obsidian task ledger; update `STATUS.md` and Obsidian current progress at task completion. Repository evidence remains authoritative if records differ.
- After Jovi reports that progress feels stalled, do not continue accumulating governance reports. At the first proof that an authority input is missing, publish one compact decision table showing: the exact missing input, what Codex can do automatically, what requires Jovi, the next milestone, and the completion definition; keep delivery progress and safety-evidence progress visibly separate.
- Treat `E:\project\jovi-automation` as the automatic-selling/product-operations control project. A product under `products\` (including Modbus) is an output of that project, not a replacement for its scope; before implementing, confirm the current thread and project-state goal so product work is not mistaken for the whole project.
- When the user corrects the project identity, freeze the correction in the execution ledger before touching code: `jovi-automation` is the Commerce control project, Modbus is only a child SKU/product, and OpenClaw is a separate project. A plan that names a product does not authorize treating that product as the main system.
- When an independent review reports candidate freeze drift, freeze all mutable status and knowledge mirrors first, then recalculate every candidate SHA from the same final tree; never treat a previously captured target-set hash as current evidence.
- After G3 Pre-Apply review passes, stop expanding governance review scope. Reduce the remaining governance work to the exact human Decision, Manifest-only APPLY, one required Post-Apply review, Gate receipt, and control-plane transition; then measure progress by working Commerce capabilities. A chat-reported PASS must still be distinguished from the auditor-owned report/sidecar needed for hash binding.
- Before declaring a governance-to-product plan executable, simulate every authorized state write against the proposed immutable Manifest. A file such as `CODEX_START_PROMPT.txt` cannot simultaneously be an immutable Framework byte and a revisioned control-plane mirror; make it a static canonical-state pointer protected by the Framework, and keep revision markers only in hash-chained state/mirror files. Also bind import target/patch objects rather than accepting naked SHA strings, and import Windows sources from fixed Git blobs instead of checkout bytes when line-ending conversion is possible.
- When a human-only PowerShell entrypoint reports duplicate `LiteralPath` binding, rerun with explicit `.Path` strings and `Join-Path` values before changing the candidate. If the explicit invocation still fails, treat the entrypoint as a candidate defect: fix it with TDD, regenerate all bound hashes, and require a fresh independent review before asking Jovi to sign again.
- For Windows PowerShell 5.1 JSON candidates, never assume direct assignment can add a missing `PSCustomObject` property. Use a tested helper that calls `Add-Member` for absent properties and updates existing properties through `PSObject.Properties`; then regenerate every transitive SHA binding and obtain a fresh independent PASS before returning the human command.
- Verification scripts must discover or assert the exact bound field names from the candidate contract before reporting a mismatch. A locally mistyped lookup such as `issue_decision_v3_script_sha256` must not be confused with an actual broken binding stored as `issue_decision_tool_sha256`.
- When a candidate binding is corrected after an independent FAIL, invalidate every prior audit result and freeze the corrected byte tree before re-auditing. A fresh PASS must recompute the candidate, sidecars, package manifest, and all transitive bindings from the same tree; never reuse the pre-fix report.
- Keep human-action parameter meanings separate: `ExpectedReviewSha256` is the bound review-package body SHA, while the independent audit report SHA is a separate evidence binding and must not be substituted at the CLI.
- Before executing a signed structural candidate, run the tool's own `--check` against the exact diff object. If the candidate's counts and the tool's frozen shape disagree, stop before APPLY and regenerate a new candidate/review; never reinterpret or hand-edit the signed V7 inputs in place.
- In Windows PowerShell 5.1 scripts using `Set-StrictMode -Version Latest`, never directly dereference an optional JSON property. Read it through `PSObject.Properties`, distinguish absent from present, and add a regression fixture that omits every optional field before asking Jovi to run the entrypoint.
- Before giving Jovi any human-only issuance command, mechanically derive every mandatory parameter from the current script signature and recompute each supplied SHA in the same turn. Never hand-transcribe a partial command or infer a missing argument from an earlier candidate revision.
- A transactional isolated APPLY test is insufficient when the transaction replaces a member consumed by an unchanged Framework entrypoint. Before any Decision, stage the full candidate after-state and execute every installed cross-file contract (including named test runners); receipt shape, target hashes and unit tests cannot substitute for that integration proof.
- When a signed structural apply fails post-apply validation, preserve the independent FAIL report before rollback, use only the signed rollback path, rehash the stable restored state after the tool completes, and bind both the failed receipt and the rollback audit into the superseding candidate.
- A frozen candidate package is the intended source for a later independent audit. Test-only staging helpers must distinguish that source manifest from a disposable staged-root manifest; never make a post-freeze integration test reject the very package state that issuance and APPLY require.
- A candidate audit must exercise the exact formal issuer output through the real executor `--check`, not only a test-local synthetic Decision. A missing executor self-SHA can pass candidate-local bindings yet correctly block immediately after human issuance; bind every entrypoint and shared dependency before requesting Decision.
- Frozen-source integration tests must copy and validate an already-final package manifest; they must never call the candidate `--prepare` writer after freeze. If that helper defect appears post-freeze, preserve the frozen candidate and build a new revision rather than thawing or editing its manifest.
- A targeted RED→GREEN helper test is not sufficient when the full suite has a second fixture path. Run the complete post-freeze suite against the exact frozen source and search every `--prepare` call before claiming the candidate is fixed.
- When a Windows PowerShell issuer compares a recursive package inventory with a forward-slash Manifest, normalize the actual relative path with a single-backslash replacement before comparing keys; preserve the failed issuance as history, add a regression test, re-freeze all transitive hashes, and re-verify the real issuer in a disposable root before returning a human command.
- A facade transaction can satisfy its own target/Framework receipt while still breaking the installed cross-file CLI: `runpy.run_path()` does not reliably expose the reviewed tool directory for sibling imports. Test each installed facade from the real root shape, add the candidate tool directory to `sys.path` before `runpy`, and rollback a signed apply before preparing a superseding Decision.
- Once Jovi has completed a human-only Decision issuance, the parent agent must execute every remaining authorized machine step itself (check, APPLY, receipt validation, closeout, and tests). Ask Jovi only for the human-only boundary; do not hand back already-authorized post-issuance commands.
- When a Git-object import tree contains both feature sources and provenance/support material, classify the complete tree into IMPORT and RECORD_ONLY_EXCLUDE rows. Rejecting every non-import path is a contract defect; preserve source commit/blob/mode/size/SHA for excluded rows and keep their target fields null.
- A superseding Decision must bind the exact schema and evidence family of every downstream verifier. A V14 strict Gate/transition tool cannot be reused with a V15 plan merely because the filenames match; stop before Approval verification and create a V15-bound verifier or a new superseding candidate.
- After V15 issuance, the remaining machine work must be implemented against the V15 schema rather than reusing V14-bound downstream tools. Keep the control-plane state binding to its exact five-field schema and put detailed Approval/verification/closeout evidence in the receipt; a disposable-root check/apply/rollback test must prove the exact three-target boundary before asking for another human decision.
- For interactive gate approvals, derive the code mechanically as `ExpectedSha256.Substring(0,16)` and count all 16 characters; never shorten it by one. In PowerShell commands, pass canonical names such as `GATE_A` and `GATE_A_PLAN.json` without Markdown escape backslashes.
- After Jovi reports a one-character approval-code mistake, treat it as a handoff defect: recompute the exact 16-character prefix from the current bound SHA, assert `Length -eq 16`, show the boundary clearly, and never reissue a stale or manually truncated prefix.
- A Git-object source selection may intentionally bind implementation/evidence commits on a separate branch from the observed external `main` bootstrap; validate the exact bound commit objects and repository state, not an invented ancestor relationship to HEAD.
- Keep phase-specific human confirmations distinct: D9 `Approve-GitBaselineV16.ps1` consumes exactly 16 characters (`d0df2009fb859b28`), while the current V17-r9 issuer consumes exactly 12 characters from its candidate (`14104a3c48d7`); derive and length-check each at the handoff instead of reusing a prefix by eye.
- Evidence-record provenance targets are not feature-worktree targets: accept only the bound `workspace/review-queue/commerce-v1/decision-to-main-x2/external-evidence/**` namespace, record them as `written=false`, and fail closed before worktree creation for any other target.
- A frozen package must be executable from its own directory: if copied tests import sibling tools, the builder must include those tool modules and a package-level suite must run before signing; source-tree tests alone do not prove package closure.
- After a formal C/APPLY, never repair a red legacy fixture or security runner in place when `FRAMEWORK_MANIFEST.sha256` binds its bytes; preserve the formal tree and use a separately bound candidate or temporary overlay for diagnosis.
